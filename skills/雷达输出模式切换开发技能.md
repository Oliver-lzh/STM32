# 雷达输出模式切换开发技能

## 使用场景

当用户要求在 RadarBaseboardMCU7 固件中开发“运行时输出模式切换”功能时使用本技能。目标是在同一个 USB CDC 虚拟串口上支持两种输出模式：

- 官方上位机协议模式：保持原厂 `HOST_PROTOCOL` 行为，兼容官方上位机。
- 普通文本调试模式：使用 `DEBUG_TEXT` 输出普通文本，方便串口助手观察变量、状态和后续算法结果。

本技能用于指导后续代码开发。单独使用本技能时，不应直接改动固件源码。

## 目标行为

后续实现应支持在串口助手中输入命令切换模式：

- `/mode host`：切换到官方上位机协议模式。
- `/mode debug`：切换到普通文本调试模式。

模式切换必须在运行时完成，不依赖重新编译。官方 `HOST_PROTOCOL` 必须始终保留为 fallback，普通文本不能污染官方上位机协议流。

## 关键设计

后续源码实现围绕 `BoardOutput` 模块展开，优先涉及：

- `BoardOutput_setMode(...)`：运行时修改当前输出模式。
- `m_mode`：保存当前模式状态。
- `BoardOutput_run()`：在主循环中处理当前模式需要持续运行的任务。
- `BoardOutput_printf(...)`：仅在 `DEBUG_TEXT` 模式下发送普通文本。

设计原则：

- 模式切换属于板级输出策略，不放入官方通信协议层。
- 通信协议层继续只负责 vendor protocol、请求解析、响应封包和 CRC。
- `DEBUG_TEXT` 模式可以直接使用 USB CDC 文本收发能力，但要避免阻塞雷达采集主循环。
- `HOST_PROTOCOL` 模式继续走 `ProtocolHandler_run()` 和 `ProtocolHandler_sendDataFrame(...)`。

## 切换流程要求

从 `DEBUG_TEXT` 切换到 `HOST_PROTOCOL` 时：

- 停止普通文本命令处理或清空临时命令缓冲。
- 初始化或恢复 `ProtocolHandler_Constructor()`。
- 注册 `RequestHandler_register(...)`。
- 注册 `Requests_Macro_register(...)`。
- 之后 `BoardOutput_run()` 只运行官方协议处理。

从 `HOST_PROTOCOL` 切换到 `DEBUG_TEXT` 时：

- 停止继续处理官方协议请求。
- 启用普通文本接收和发送路径。
- 确认不会继续调用会向上位机发送二进制协议帧的路径。
- 之后 `BoardOutput_printf(...)` 才允许输出文本。

切换动作必须只做一次初始化或收尾，不要在每次主循环重复初始化。

## 命令解析要求

第一阶段只实现最小命令集：

```text
/mode host
/mode debug
```

解析规则：

- 只在 `DEBUG_TEXT` 模式读取文本命令。
- 一次读取一行命令，以换行或回车换行作为结束。
- 未知命令只返回简短提示，不改变模式。
- 命令解析不得长时间阻塞主循环。

如果当前处于 `HOST_PROTOCOL` 模式，默认不解析普通文本命令，避免把官方上位机二进制协议误当成文本命令。

## 多 Subagent 分工

后续实现该功能时，使用多 subagent 模式，但最终决策仍由 Root 主控集成者负责。

### Root 主控集成者

职责：

- 冻结需求和接口边界。
- 指定每个 Agent 的文件范围和禁止修改范围。
- 合并实现结果。
- 决定最终是否可以编译、烧写和交付。

Root 不把最终判断交给子 Agent。

### 实现 Agent

职责：

- 按 Root 指定范围写代码。
- 优先修改 `BoardOutput.c` 和 `BoardOutput.h`。
- 必要时才修改 `Board.c` 的调用点。
- 不改 HAL、ASF、CMSIS、SPI、DMA、雷达采集底层驱动。

实现重点：

- 添加 `BoardOutput_setMode(...)`。
- 添加最小命令解析。
- 保证 `HOST_PROTOCOL` 和 `DEBUG_TEXT` 两种路径互不污染。

### 审查/测试 Agent

职责：

- 检查是否存在协议污染风险。
- 检查 USB CDC 发送是否可能阻塞主循环。
- 检查模式切换状态是否一致。
- 检查缓冲区长度、字符串截断、命令解析边界。
- 检查是否误改官方通信协议层。

审查结果必须指出具体文件、函数和风险。

### 构建验证 Agent

职责：

- 检查 Atmel Studio 工程和 Makefile。
- 确认使用 Atmel Studio 自带 ARM GCC 6.3.1。
- 不使用 STM32CubeCLT GCC 13.3.1。
- 分别验证 Release 和 Debug 编译。
- 检查 `.bin`、`.elf`、`.map` 是否生成。
- 检查 `.map` 中 Flash 和 SRAM 余量是否安全。

构建失败时，优先定位工具链路径和新增文件是否加入构建。

### 专项分析 Agent

需要时临时启用，负责专项问题：

- USB CDC 接收和发送边界。
- `ProtocolHandler` 与 `RequestHandler` 初始化关系。
- 雷达帧 `payload/count/channel/timestamp` 数据路径。
- `Board_dataCallback()` 与输出模式之间的关系。

专项分析 Agent 默认只读，除非 Root 明确授权其修改指定文件。

## 实施顺序

推荐后续按以下顺序开发：

1. 先确认现有 `BoardOutput.c`、`BoardOutput.h`、`Board.c` 的当前状态。
2. 添加 `BoardOutput_setMode(...)` 接口。
3. 在 `DEBUG_TEXT` 模式下增加非阻塞命令读取。
4. 实现 `/mode host` 和 `/mode debug` 两个命令。
5. 为模式切换添加一次性初始化或收尾保护。
6. 编译验证 Release 和 Debug。
7. 烧写后先验证默认模式，再验证文本模式，再验证切回官方模式。

## 验证要求

后续代码实现完成后，至少验证：

- 默认模式仍能兼容官方上位机。
- `DEBUG_TEXT` 模式下串口助手能看到普通文本输出。
- 输入 `/mode host` 后不再输出普通文本。
- 输入 `/mode debug` 后可以再次输出普通文本。
- 切换过程中固件不应卡死。
- 雷达采集不应因为 USB CDC 发送或命令解析而停止。
- Release 和 Debug 编译均成功。
- `.bin`、`.elf`、`.map` 均正常生成。

## 禁止事项

- 不把普通文本命令解析塞进官方 vendor protocol 层。
- 不在 `HOST_PROTOCOL` 模式下主动输出普通文本。
- 不在主循环中重复初始化 `ProtocolHandler` 或 `SerialPort`。
- 不改底层 HAL、ASF、CMSIS、SPI、DMA。
- 不删除官方上位机协议路径。
- 不使用错误工具链编译。

## 当前阶段边界

本文件只是后续开发技能说明。当前阶段不修改：

- `Board.c`
- `BoardOutput.c`
- `BoardOutput.h`
- 官方通信协议层源码
- 雷达采集底层源码

真正开始实现运行时模式切换时，必须重新确认当前代码状态，再按本技能启用多 subagent 开发和构建验证。
